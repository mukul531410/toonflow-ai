# Kilo Code Rules

Before making changes, read the relevant files in `docs/` and follow the shared development rules in `docs/DEVELOPMENT_RULES.md`. The shared documentation is the project source of truth.

Prefer small, clearly scoped implementation tasks. Inspect files before editing. Avoid architectural changes unless explicitly requested, never introduce dependencies without approval, and never modify unrelated files.

After each task, report files changed and testing performed.
